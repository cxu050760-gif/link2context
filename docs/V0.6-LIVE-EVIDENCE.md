## 证据状态

- `PASS`：真实浏览器已验证。
- `FAIL`：真实浏览器已复现失败。
- `PASS / PARTIAL`：核心能力真实可用，但已知存在信息缺失，不能称完整成功。
- `UNVERIFIED`：当前候选/版本尚未真实验证。
- `BLOCKED`：因账号、权限、验证码或外部条件无法验证。

- **V0.6.1 实现收口点**：commit `8f413c262ad7cbff16b367b663eebf65a8ee3b8a`；`npm run check` PASS；`npm test` **350 / 350 PASS**；GitHub Actions **CI #515 SUCCESS**。
- V0.6.1 的这些自动化结果证明本轮安全/可靠性契约闭环，**不证明第三方网页 UI 仍然兼容**。

## 未来恢复项目时的 live gate

在把 V0.6.1 从 Draft 提升为稳定候选前，至少重新完成：

1. ChatGPT / DeepSeek / 豆包 / 千问：普通网页手动文本交付各 1 次真实 PASS；
2. 千问：V0.5.3 的“可编辑、可删除”能力在 V0.6.1 上继续 PASS；
3. 至少一个真实图文网页证明：正文 + 关键图片同时交给目标 AI，图片失败时不会静默自动发送；
4. 至少一个 PDF / 图片等原始二进制附件路径不回归；
5. Auto-send 每个目标单独记录；未 PASS 的目标必须 fail-closed（失败时不假装成功），且不阻塞默认手动模式；
6. STOP 至少覆盖网络抓取、渲染等待、媒体下载、页面交付和发送等待。

## 最终状态原则

> **CI PASS ≠ Live PASS。历史 PASS ≠ 新版本 PASS。没有真实证据就保持 UNVERIFIED；真实失败就保留 FAIL，直到同一候选版本重新验证成功。**
