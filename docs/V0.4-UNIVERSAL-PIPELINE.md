# Link2Context V0.4.0 — 通用 URL 管线加固 / Universal URL Pipeline Hardening

## 中文

V0.4.0 的目标不是继续给某个网站堆特判，而是把 Link2Context 的通用主链冻结成五层：

```text
Acquire / 获取
  ↓
Classify / 类型识别
  ↓
Render if needed / 必要时渲染
  ↓
Extract / 清洗提取
  ↓
Handoff / 交付
```

本版本来自 2026-08-22 的实机兼容性测试：普通 HTML、长页面和 JSON 主链已经成立，但 PDF 被误解码为文本、401/403 被错误归入 handoff、JS shell 无明确分类、正文噪声和分页仍有缺口。

### 1. Acquire / 获取

网络失败现在保留结构化错误，而不是最后都显示“页面交付失败”：

| HTTP / failure | code | stage |
|---|---|---|
| 401 | `AUTH_REQUIRED_401` | `AUTH` |
| 403 | `FETCH_BLOCKED_403` | `FETCH` |
| 404 | `NOT_FOUND_404` | `FETCH` |
| 429 | `RATE_LIMITED_429` | `FETCH` |
| 5xx | `HTTP_5XX` | `FETCH` |
| timeout | `FETCH_TIMEOUT` | `FETCH` |
| network | `FETCH_NETWORK_ERROR` | `FETCH` |
| too large | `RESPONSE_TOO_LARGE` | `FETCH` |

401/403/404/429 不会无意义反复重试；5xx、网络错误和超时仍可做受限重试。HTTPS Fake-IP/TUN 兼容回退只对符合条件的网络错误生效，并继续重验每次重定向。

### 2. Classify / 类型识别

V0.4 改成 **byte-first（先看原始字节）**，不再先 `decodeBytes()` 再猜是不是文本。

识别顺序综合：

1. Magic Header / 文件签名；
2. Content-Type / MIME；
3. URL 文件扩展名；
4. 文本字节可读性与 JSON/HTML sniff。

目前直接识别并保持原文件附件的类型包括 PDF、常见图片、ZIP/7z/RAR/gzip、Office 文档、常见音频和视频。即使服务端错误声称 `text/plain`，`%PDF-`、PNG/JPEG 等强签名仍优先；反过来，Content-Type 声称 HTML/JSON，但字节明显是二进制时也 fail-closed 为 binary。

核心规则：

> Binary 默认走原文件附件，禁止默认 decode 成文本。

### 3. Render / 渲染边界

普通 HTML 会先判断是否只有 JS shell / 空壳：空 `#root`、`#app`、`#__next`、明确要求启用 JavaScript、超大 HTML 但有效正文极少等情况，会返回：

```text
CLIENT_RENDER_CONTENT_MISSING
stage = RENDER
```

V0.4 **不会自动把通用 browser fallback 扩展到任意 URL**。原因是浏览器导航会携带当前 Cookie / Session；若静默读取登录后 DOM，再把内容发送到另一个 AI，会把“网页抓取能力”变成潜在的私有会话外传通道。

WorkBuddy 与 ChatGPT Share 既有 fallback 继续保持精确域名/路径白名单，因为它们是明确的公开分享数据源。

后续如果加入通用浏览器渲染，应做成显式授权能力，而不是默认行为。

### 4. Extract / 正文清洗

轻量 HTML 清洗现在：

- 优先语义 `<main>` / `<article>`；
- 删除 script/style/noscript/template/svg/canvas/iframe；
- 删除 nav/footer/aside/form/dialog/menu/button/select；
- 删除常见 nav/menu/sidebar/footer/toolbar/breadcrumb/language/login/cookie/modal 等 UI wrapper；
- 保留短小合法静态页，不因为正文短就误判为 shell。

这仍是零依赖轻量实现，不宣称等价于 Mozilla Readability、Defuddle、Trafilatura。设计上继续遵循 **Reuse > Adapt > Compose > Build from scratch**；若后续正文质量成为主要瓶颈，应优先评估把成熟正文抽取器作为可审计依赖/构建产物，而不是无限扩展正则规则。

### 5. Pagination / 安全分页

V0.4 增加受限自动追页：

- `rel=next`；或
- 明确“下一页 / Next / Older”等链接，并且 URL 必须仍属于同一文章 family；
- 必须同源；
- 最多 8 页；
- 后续每页最多 3 MiB；
- 所有页面合计仍受全局 12 MiB 上限；
- visited set 防循环；
- 后续某页失败时返回已获取正文并标记 `PARTIAL`，不会把第一页也丢掉。

不做跨站追页，也不会因为普通“Next”文字就跳到另一篇文章。

### 6. Handoff / 交付

交付继续同时考虑内容类型和目标 AI：

- PDF / image / archive / Office / audio / video / unknown binary → 原文件附件；
- HTML / JSON / text → 清洗后的上下文；
- ChatGPT + conversation source → Markdown 附件优先；
- ChatGPT 普通大文本 → 较低软阈值转附件；
- 其他目标保留全局硬阈值。

页面端现在保留后台错误的 `errorCode / errorStage / statusCode`，所以 `FETCH_BLOCKED_403` 不再被重写为 `HANDOFF_ERROR`。

## 对实机报告中几个案例的预期变化

| 案例 | V0.3.1 | V0.4.0 代码层预期 |
|---|---|---|
| W3C PDF | PDF 被当文本 | `%PDF-` 识别后原 PDF 附件 |
| Wikimedia 403 | 泛化失败 | 明确 `FETCH_BLOCKED_403`；**不声称绕过 403** |
| WSJ 401 | 泛化失败 | 明确 `AUTH_REQUIRED_401`；**不绕过登录/付费墙** |
| Instagram shell | 只有标题/低价值内容 | 明确 `CLIENT_RENDER_CONTENT_MISSING / RENDER` |
| GitHub / Wikipedia | 正文 + 很多 UI | 更优先 main/article 并去除常见 UI |
| 1/8 分页新闻 | 只取第一页 | 同源、同文章 family 可检测时最多自动追 8 页 |

这些是代码路径和自动测试保证，不等同于对应外部网站已经完成实机验收。站点行为、CDN 策略和网页 DOM 随时可能变化。

## English

V0.4.0 hardens the generic URL pipeline instead of adding another set of site-specific parsers.

The pipeline is explicitly separated into **Acquire → Classify → Render if needed → Extract → Handoff**. Binary classification is byte-first, with magic signatures, MIME, extension hints, and text sniffing. Binary resources default to original-file attachments and are never decoded as text merely because a server supplied a misleading textual Content-Type.

Fetch failures now retain structured codes and stages (`AUTH_REQUIRED_401`, `FETCH_BLOCKED_403`, `RATE_LIMITED_429`, `FETCH_TIMEOUT`, etc.). Shell-only HTML is reported as a `RENDER` problem. Generic browser-session fallback remains intentionally disabled by default because silently carrying logged-in cookies into arbitrary navigation could expose private content to the destination AI.

HTML cleaning favors semantic `main/article` content and removes common navigation/sidebar/footer wrappers. Safe pagination is same-origin, bounded to eight pages, globally byte-capped, loop-protected, and partial-failure tolerant.

V0.4 does **not** claim to bypass authentication, CDN blocking, CAPTCHAs, paywalls, or client-only rendering. It makes those boundaries explicit and machine-readable while fixing the dangerous binary-as-text class of failures.
