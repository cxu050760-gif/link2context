# Link2Context V0.6.1 Hardening / 加固记录

V0.6.1 是 V0.6.0 的安全与可靠性补丁版，不扩大产品范围，不把任何缺少真实浏览器证据的第三方能力从 `UNVERIFIED`（未验证）升级为 PASS。

本轮先完成 20 个 adversarial rounds（对抗轮次），在首轮 CI 暴露旧测试契约后修正测试，再继续做 2 个 follow-up rounds（追加轮次）。所有修复都要求 fail-closed（失败时不假装成功），并尽量复用 V0.5.3 / V0.6 已验证路径。

## 20 个核心攻击轮次

| # | 攻击面 | 攻击方式 | 结果 / 修复 |
|---|---|---|---|
| 1 | Public address-space guard（公网地址空间保护） | 诱导网络兼容回退移除 `targetAddressSpace` | 默认严格保护保留；只有显式兼容开关才允许受限回退 |
| 2 | HTTP error typing（HTTP 错误类型） | 401/403/404/429 被误重试或进入兼容回退 | 非重试错误保持 typed failure（类型化失败），不进入兼容回退 |
| 3 | Redirect safety（重定向安全） | 公网 URL 重定向到 localhost / 私网 / HTTPS→HTTP | 每跳重新验证；私网与降级重定向 fail-closed |
| 4 | AI-facing URL secret leakage（面向 AI 的 URL 密钥泄露） | OAuth code、token、signature、session 等 query 值进入上下文 | 敏感 query key 统一脱敏，hash（片段）移除 |
| 5 | Debugger host confinement（调试器域名约束） | 非允许 host 调用 CDP | 仅固定 Qianwen / ChatGPT / DeepSeek / Doubao 范围 |
| 6 | Debugger TOCTOU（检查-使用竞态） | attach 后页面跳转，再执行 `Input.insertText` / Enter | 每个输入命令前重新读取当前 tab URL 并校验 host |
| 7 | Generic debugger surface（通用调试器暴露面） | 试图通过 V0.6 generic CDP 注入任意文本 | generic surface 只允许 Enter；文本注入仅保留千问专用路径 |
| 8 | Job identity / STOP（任务身份 / 停止） | 旧任务 STOP 误杀新任务 | foreground/background 共享 `startedAt` 任务身份；stale STOP 不取消新任务 |
| 9 | Upstream partial propagation（上游部分完成传播） | 抓取不完整却继续自动发送 | `partial/sourcePartial/mediaPartial` 向交付层传播；自动发送关闭 |
| 10 | Media partial（媒体部分失败） | 正文成功但关键图片失败后仍报告完整成功 | 媒体失败变成显式 partial，并禁止自动发送 |
| 11 | Attachment input hijack（附件入口劫持） | 页面中无关 `<input type=file>` 被误选 | 优先 composer scope（输入区范围）；仅允许菜单动作后出现的新兼容 input 作为回退 |
| 12 | Attachment false proof（附件假证据） | 页面其他区域出现同名文本，伪造“附件已上传” | 文件名确认限制在当前 composer/附件区域 |
| 13 | `accept` bypass（上传类型限制绕过） | 临时移除 input `accept` 强塞不兼容文件 | 不再解除网站限制；无兼容入口就明确失败 |
| 14 | Original binary preservation（原始二进制保留） | PDF/图片/Office/压缩包被误转成文本 | 原文件继续走附件 fallback；二进制不可落入文本规范化路径 |
| 15 | Image cancellation semantics（图片取消语义） | 用户 STOP 被吞成“部分图片失败” | `USER_CANCELLED` 继续抛出，不降级为 partial success |
| 16 | Render authorization recheck（渲染授权复查） | 授权后导航到 deny-list 站点 | 页面导航后重新检查授权与 deny-list |
| 17 | Render origin pinning（渲染来源域固定） | 授权页跨 origin 跳转后继续采集 | 绑定初始 `expectedOrigin`，跨 origin 立即停止 |
| 18 | Load-more side effects（加载更多副作用） | 恶意页面把提交/订阅按钮标记为“Load more” | 自动加载更多不点击 form / submit 控件，跨源 anchor 也拒绝 |
| 19 | Pagination identity（分页文章身份） | “下一页”实际指向下一篇文章 | Article Identity 校验；身份不符停止并标记 partial |
| 20 | Parser/resource exhaustion（解析资源耗尽） | 巨型表格、超长单元格、海量列表、深层结构 | 表格行/列/单元格和列表数量均设置上限，达到上限显式 `structuredTruncated` |

## 追加 2 个 follow-up rounds / 后续迭代

### 21. Debugger scheme downgrade / 调试器协议降级

攻击：允许域名在 `http://` 页面或 attach 后降级为 HTTP，再使用 CDP 输入。

修复：调试器入口和每次命令前的 current-tab revalidation（当前标签页复查）现在都要求 `https:`。允许域名但非 HTTPS 也会 fail-closed。

### 22. Debugger failure classification / 调试器失败分类

攻击：CDP 已成功 attach，但后续 `Input.*` 命令失败，被错误报告为 `*_ATTACH_FAILED`，导致诊断失真。

修复：attach failure（连接失败）与 command failure（命令失败）分离；分别返回 `*_ATTACH_FAILED` / `*_COMMAND_FAILED`，已占用继续返回 `*_BUSY`，导航越界继续保留专用 `*_NAVIGATION_DENIED`。

## 回归原则

- `npm run check` 必须通过。
- 全量 `npm test` 必须通过。
- GitHub Actions CI 必须在最终 head（最终提交）全绿。
- CI 只证明代码与自动化契约，不自动证明第三方网页 UI 仍然兼容。
- V0.5.3 千问真实浏览器 PASS 继续只是历史基线；V0.6/V0.6.1 未重新实测的能力仍保持 `UNVERIFIED`。

## Scope freeze / 范围冻结

V0.6.1 只修 correctness（正确性）、security（安全）、reliability（可靠性）、truthfulness（状态真实性）问题。没有新增模型、没有扩大目标网站范围、没有增加绕过登录/验证码/付费墙能力，也没有把 `debugger` 变成通用网页自动化接口。
