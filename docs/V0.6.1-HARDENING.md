# Link2Context V0.6.1 Hardening / 加固记录

V0.6.1 是 V0.6.0 的安全与可靠性补丁版，不扩大产品范围，不把任何缺少真实浏览器证据的第三方能力从 `UNVERIFIED`（未验证）升级为 PASS。

> **阶段性收尾：2026-08-23。** PR #12 保持 Draft（草稿）、未合并；当前 `main` 仍是 V0.6.0。V0.6.1 实现收口点 `8f413c262ad7cbff16b367b663eebf65a8ee3b8a` 已通过 `npm run check`、**350 / 350** 自动化测试和 GitHub Actions **CI #515**。本轮没有重新完成 ChatGPT / DeepSeek / 豆包 / 千问四平台 live-browser gate（真实浏览器门禁），因此 V0.6.1 仍是 **CODE PASS / LIVE UNVERIFIED** 的加固候选，不标记为稳定发行版。版本选择与已知失败见 [`PROJECT-STATUS.md`](./PROJECT-STATUS.md)，真实证据见 [`V0.6-LIVE-EVIDENCE.md`](./V0.6-LIVE-EVIDENCE.md)。

本轮先完成 20 个 adversarial rounds（对抗轮次），在首轮 CI 暴露旧测试契约后修正测试，再继续做 2 个 debugger follow-up rounds（追加轮次），随后又对实际 manifest 加载链、legacy fallback、授权浏览器与交付副作用做独立红队攻击。所有修复都要求 fail-closed（失败时不假装成功），并尽量复用 V0.5.3 / V0.6 已验证路径。

## 20 个核心攻击轮次

| # | 攻击面 | 攻击方式 | 结果 / 修复 |
|---|---|---|---|
| 1 | Public address-space guard（公网地址空间保护） | 诱导网络兼容回退移除 `targetAddressSpace` | 默认严格保护保留；只有显式兼容开关才允许受限回退 |
| 2 | HTTP error typing（HTTP 错误类型） | 401/403/404/429 被误重试或进入兼容回退 | 非重试错误保持 typed failure（类型化失败），不进入兼容回退 |
| 3 | Redirect safety（重定向安全） | 公网 URL 重定向到 localhost / 私网 / HTTPS→HTTP | 每跳重新验证；私网与降级重定向 fail-closed |
| 4 | AI-facing URL secret leakage（面向 AI 的 URL 密钥泄露） | OAuth code、token、signature、session 等 query 值进入上下文 | 敏感 query key 统一脱敏，hash（片段）移除 |
| 5 | Debugger host confinement（调试器域名约束） | 非允许 host 调用 CDP | 仅固定 Qianwen / ChatGPT / DeepSeek / Doubao 范围 |
| 6 | Debugger TOCTOU（检查-使用竞态） | attach 后页面跳转，再执行 `Input.insertText` / Enter | 每个输入命令前重新读取当前 tab URL 并校验 host |
| 7 | Generic debugger surface（通用调试器暴露面） | 试图通过 V0.6 generic CDP 注入任意文本 | generic surface 只允许 Enter；文本注入仅保留千问专用路径 |
| 8 | Job identity / STOP（任务身份 / 停止） | 旧任务 STOP 误杀新任务 | foreground/background 共享 `startedAt` 任务身份；stale STOP 不取消新任务 |
| 9 | Upstream partial propagation（上游部分完成传播） | 抓取不完整却继续自动发送 | `partial/sourcePartial/mediaPartial` 向交付层传播；自动发送关闭 |
| 10 | Media partial（媒体部分失败） | 正文成功但关键图片失败后仍报告完整成功 | 媒体失败变成显式 partial，并禁止自动发送 |
| 11 | Attachment input hijack（附件入口劫持） | 页面中无关 `<input type=file>` 被误选 | 优先 composer scope（输入区范围）；仅允许菜单动作后出现的新兼容 input 作为回退 |
| 12 | Attachment false proof（附件假证据） | 页面其他区域出现同名文本，伪造“附件已上传” | 文件名确认限制在当前 composer/附件区域 |
| 13 | `accept` bypass（上传类型限制绕过） | 临时移除 input `accept` 强塞不兼容文件 | 不再解除网站限制；无兼容入口就明确失败 |
| 14 | Original binary preservation（原始二进制保留） | PDF/图片/Office/压缩包被误转成文本 | 原文件继续走附件 fallback；二进制不可落入文本规范化路径 |
| 15 | Image cancellation semantics（图片取消语义） | 用户 STOP 被吞成“部分图片失败” | `USER_CANCELLED` 继续抛出，不降级为 partial success |
| 16 | Render authorization recheck（渲染授权复查） | 授权后导航到 deny-list 站点 | 页面导航后重新检查授权与 deny-list |
| 17 | Render origin pinning（渲染来源域固定） | 授权页跨 origin 跳转后继续采集 | 绑定初始 `expectedOrigin`，跨 origin 立即停止 |
| 18 | Load-more side effects（加载更多副作用） | 恶意页面把提交/订阅按钮标记为“Load more” | 自动加载更多不点击 form / submit 控件，跨源 anchor 也拒绝 |
| 19 | Pagination identity（分页文章身份） | “下一页”实际指向下一篇文章 | Article Identity 校验；身份不符停止并标记 partial |
| 20 | Parser/resource exhaustion（解析资源耗尽） | 巨型表格、超长单元格、海量列表、深层结构 | 表格行/列/单元格和列表数量均设置上限，达到上限显式 `structuredTruncated` |

## 追加 2 个 debugger follow-up rounds / 调试器追加轮次

### 21. Debugger scheme downgrade / 调试器协议降级

攻击：允许域名在 `http://` 页面或 attach 后降级为 HTTP，再使用 CDP 输入。

修复：调试器入口和每次命令前的 current-tab revalidation（当前标签页复查）现在都要求 `https:`。允许域名但非 HTTPS 也会 fail-closed。

### 22. Debugger failure classification / 调试器失败分类

攻击：CDP 已成功 attach，但后续 `Input.*` 命令失败，被错误报告为 `*_ATTACH_FAILED`，导致诊断失真。

修复：attach failure（连接失败）与 command failure（命令失败）分离；分别返回 `*_ATTACH_FAILED` / `*_COMMAND_FAILED`，已占用继续返回 `*_BUSY`，导航越界继续保留专用 `*_NAVIGATION_DENIED`。

## 独立红队追加攻击 / Independent follow-up red team

原 20+2 完成后，没有直接把旧 CI 绿色当最终结论，而是继续针对实际加载的 V0.6 + V0.5.3 fallback 链做攻击。新增重点如下：

| 攻击面 | 发现 | 收口结果 |
| --- | --- | --- |
| Trailing-dot host aliases | `localhost.` / `.local.` / metadata hostname 末尾点可能绕过字符串式主机判断 | URL 安全层先规范化 hostname，等价本机/metadata alias 继续被阻止 |
| Unexpected HTTP 206 | 非 Range 请求若收到 `206 Partial Content` 可能被误当完整正文 | 显式返回 `UNEXPECTED_PARTIAL_CONTENT_206`，不把部分字节冒充完整资源 |
| Legacy authorized-browser origin | 401/403/render fallback 的旧浏览器路径缺少与 V0.6 一样明确的 initial-origin pin | legacy browser acquisition 绑定 `expectedOrigin`；跨 origin 返回 `BROWSER_CONTEXT_CROSS_ORIGIN_NAVIGATION` |
| Credentialed binary redirect | 授权标签页内 `credentials: include` 的二次 fetch 若自动 follow redirect，可能把凭据语义带入第二来源 | 使用 `redirect: 'error'`；外层再校验最终 URL/origin |
| V0.6 → legacy STOP | V0.6 fallback 到 legacy 后，如果 STOP 只取消 V0.6 pipeline，后台旧任务可能继续 | 同一 `startedAt` identity 同时传入 V0.6/legacy resolve 与 cancel |
| Legacy owner STOP | manifest 中实际加载的 `content-script-v053.js`、`qianwen-cdp-v053.js`、`qwen-state-bridge-v053.js` 也必须传播 exact identity | 三条 legacy owner 都回传相同 `startedAt` 给 legacy background |
| Resolve replacement ordering | 非授权/非真实手势消息如果先替换 active job，再做 gate，可中止合法任务 | sender/user-gesture gate 先于 previous-job abort |
| Disabled / accept attachment fallback | helper 抽象或 legacy fallback 可能绕过 `disabled` / `aria-disabled` / `accept` | V0.6 和已加载 legacy Qwen/Qianwen owner 都走 fail-closed 检查 |
| Pre-existing same-name proof | 页面在上传前已有同名文本时，可能把旧文本当“上传成功” | 上传前记录文件名可见状态；只有新出现证据才算确认 |
| Multiple send side effects | 第一个 click/form/Enter 可能已发送但检测没确认，再执行第二策略可能重复发送 | 第一次有副作用但未确认即停止，返回 `SEND_UNCONFIRMED`，不链式二次提交 |
| Markdown fence breakout | 来源代码包含 ``` 时可能提前闭合固定 fence | 输出 fence 长度按内容扩展，外部代码不能逃逸 canonical data block |
| Brittle source-shape tests | 多条旧测试锁死旧 helper/源码形状，生产实现变严后反而误报失败 | 改为验证真实行为契约；未为测试绿灯放宽生产边界 |

## Scope freeze / 范围冻结

V0.6.1 只修 correctness（正确性）、security（安全）、reliability（可靠性）、truthfulness（状态真实性）问题。没有新增模型、没有扩大目标网站范围、没有增加绕过登录/验证码/付费墙能力，也没有把 `debugger` 变成通用网页自动化接口。

## 阶段性封存 / Temporary project closeout

项目暂时停止继续扩展。PR #12 保持 Draft，不 merge 到 `main`。这不是因为还有已知自动化 blocker，而是因为：

1. 实现层安全/可靠性攻击已形成可复用的 350-test 自动化基线；
2. 第三方网页 UI 兼容性必须靠真实浏览器验证，不能继续用单元测试冒充；
3. 用户当前选择阶段性收尾，而不是继续无限修补；
4. 未来恢复时，应先跑 `docs/V0.6-LIVE-EVIDENCE.md` 里的最小 live gate，再决定是否合并 V0.6.1。

最终原则：

> **CODE PASS 不等于 LIVE PASS。历史 PASS 不等于新候选 PASS。没有证据就保持 UNVERIFIED；真实失败就保留 FAIL，直到重新验证。**
