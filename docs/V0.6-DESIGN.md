# Link2Context V0.6 Design / 设计稿

## 0. 版本定位

V0.6 不是继续给 V0.5.3 堆站点补丁，而是把项目从“URL → 纯文本/附件”升级为：

> URL / resource → acquisition → structured context → target profile → reliable handoff
>
> 链接/资源 → 采集 → 结构化上下文 → 目标 AI 能力画像 → 可靠交付

V0.5.3 的稳定能力（URL 安全、授权浏览器上下文、二进制原文件、STOP、千问 CDP、fail-closed 发送证据）继续保留。

## 1. V0.6 必须解决的核心问题

### P0-1 Structured Context / 结构化上下文

当前 `html-lite.js` 会把 HTML 大量压扁成纯文本。V0.6 引入统一 Context Model，至少保留：

- title / author / published time / canonical URL；
- heading；
- paragraph；
- list；
- blockquote；
- code block + language；
- table；
- link；
- image + alt/caption/source URL；
- attachment；
- source/provenance；
- trust classification。

外部网页、文件和图片统一标记为 untrusted external data，Target Adapter 必须把“外部内容是数据，不是用户/系统指令”的边界带入最终交付。

### P0-2 Mature extraction reuse / 成熟提取方案复用

不再继续扩展正则 Reader Mode。

首选路线：

1. Mozilla Readability：负责正文区域识别和文章元数据；
2. DOM-based structured walker：从正文 DOM 生成 Context blocks；
3. Markdown 只作为一种 renderer，不再是 canonical state。

Readability 输出仍需 sanitizer / 安全清洗；不执行外部脚本。

### P0-3 Images and mixed media / 图文混合内容

普通网页不能再只交纯文本。

V0.6 需要：

- `src` / `srcset` / lazy-load data attributes；
- 相对 URL 绝对化；
- tracking pixel / logo / avatar / ad noise filtering；
- image dedupe；
- caption / nearby text relation；
- per-image + total-byte limits；
- authenticated image fallback only after explicit browser-context authorization；
- target AI 不支持多图时按 Target Profile 降级为文档 + image manifest，而不是静默丢图。

### P0-4 Target Adapter / 目标 AI 适配器

V0.6 正式拆出 target adapters，而不是继续把所有目标站点揉在 `content-script-v053.js`。

每个 Target Profile 至少描述：

- hosts；
- composer acquisition；
- supported handoff modes；
- supported/verified attachment families；
- safe text threshold；
- reliable send strategies；
- post-send evidence；
- debugger requirement；
- official capability evidence；
- Link2Context live-tested capability；
- last verified date。

发送 fallback ladder：

1. target-supported DOM / form / explicit page API；
2. browser-native interaction；
3. CDP only when a target demonstrably requires it；
4. fail closed and leave content ready for manual send。

千问继续使用已实测通过的 CDP 路径；不得因为千问成功就把所有目标默认迁到 CDP。

### P0-5 Real Browser Evidence / 真实浏览器证据制度

CI PASS 不再等于 live PASS。

固定记录：

- extension version / commit；
- browser version；
- target AI；
- date；
- test account class if relevant；
- input sentinel；
- handoff mode；
- editable/deleteable state；
- attachment registration；
- auto-send post evidence；
- screenshot/log when failed；
- verdict PASS / FAIL / BLOCKED。

V0.6 merge gate 至少覆盖 ChatGPT、DeepSeek、豆包、千问的文本手动交付；Auto-send 作为独立 capability 验证，不阻塞用户默认手动模式，但启用时必须真实可用或明确失败。

## 2. V0.6 非目标 / 防止 Scope 再膨胀

V0.6 不承诺：

- 任意网站无限滚动全部自动完成；
- 所有 AI 的所有附件类型都支持；
- 所有目标站点都使用 CDP；
- 通用网页自动点击任意“加载更多”；
- 视频/音频理解本身；
- 绕过登录、验证码、DRM、付费墙或站点访问控制。

动态网页在 V0.6 只建立 Rendered Acquisition 基础状态机和有限能力，不一次解决所有 SPA。

## 3. Rendered Acquisition State Machine / 渲染采集状态机

状态：

`NAVIGATE → MAIN_CONTENT_FOUND → DOM_SETTLING → OPTIONAL_EXPAND → CAPTURE → DEDUPE → COMPLETE`

约束：

- deadline；
- max scrolls；
- max DOM growth；
- max pages；
- max bytes；
- STOP cancellation；
- same-origin / authorization boundary；
- no blind clicking outside explicit candidate controls。

第一阶段只处理：

- JS render 后正文出现；
- 有明确 load-more / next semantics 的有限扩展；
- 不处理无界无限滚动。

## 4. Pagination correctness / 分页正确性

URL family 继续作为候选信号，但不再作为唯一真值。

新增 Article Identity：

- canonical URL；
- title/H1 similarity；
- author/date continuity；
- main-container similarity；
- text overlap / duplicate fingerprint；
- page-number continuity。

候选页需要同时证明“像下一页”和“仍属于同一内容”。宁可停止，也不要静默串入另一篇文章。

## 5. Encoding / 编码

解码顺序：

`BOM → HTTP charset → HTML/XML declaration → UTF-8 validity → bounded fallback`

Context metadata 保存：

- detected charset；
- source of charset decision；
- confidence / fallback flag。

GBK/GB18030、Big5、Shift_JIS 至少进入测试矩阵。

## 6. Capability truth model / 能力真值模型

区分三类值：

1. `official`：官方公开能力；
2. `l2c_safe`：Link2Context 自身保守阈值；
3. `live_verified`：真实浏览器验证过的当前能力。

禁止把内部安全阈值写成“平台官方上限”。所有 platform capability 都必须带 `verifiedAt` / evidence provenance。

## 7. AI-Exporter / ChatArchive 可复用经验

### AI-Exporter 值得借鉴

- `platform.js` 将 host → platform config → api/parser 分开；
- ChatGPT、Claude、Gemini、DeepSeek、Grok 等各自有 API/parser 模块；
- API 优先、DOM fallback 的方向比单一全站 DOM selector 更健康；
- 导出错误记录、partial failure、平台感知品牌/格式等工程习惯值得借鉴。

但不直接照搬：

- DeepSeek 适配当前硬编码 `/api/v0` 并从 `localStorage.userToken` 取 token，属于高漂移私有接口；
- 平台私有 API 必须有版本漂移检测和 DOM/browser fallback；
- 不能把“支持 DeepSeek”视为永久真值。

### ChatArchive 值得借鉴

- state/api/page/dom 多路径；
- extraction source / strategy / confidence 诊断；
- scheduled live smoke；
- debug report；
- API/state path 优先，DOM path fallback。

V0.6 将吸收“strategy + evidence + fallback”思想，但不复制与 Link2Context 目标无关的导出功能。

## 8. V0.6 分阶段交付

### M1 — Context foundation

- Context Model + provenance/trust；
- Readability integration path；
- structure-preserving renderer；
- image inventory；
- regression fixtures。

### M2 — Target adapters

- ChatGPT；
- DeepSeek；
- Doubao；
- Qianwen（迁移现有 CDP adapter，不重写已 PASS 逻辑）；
- manual handoff first；
- auto-send as separately verified capability。

### M3 — Rendered acquisition

- rendered-main-content wait；
- bounded DOM settle；
- limited load-more/next；
- identity/dedupe。

### M4 — Encoding + capability profiles + live evidence

- legacy charset；
- capability metadata；
- live smoke record format；
- final README / SECURITY / CHANGELOG / release notes。

## 9. Merge gates

V0.6 不因单元测试全绿直接合并。

必须同时满足：

- current unit/regression tests PASS；
- new context fixtures PASS；
- security tests PASS；
- no silent loss of critical image/table/code structure in fixture set；
- ChatGPT manual text handoff live PASS；
- DeepSeek manual text handoff live PASS；
- Doubao manual text handoff live PASS；
- Qianwen manual text handoff live PASS；
- Qianwen prior regression remains PASS；
- failed auto-send never reports success；
- STOP remains fail-safe；
- docs list verified vs unverified capabilities honestly。
