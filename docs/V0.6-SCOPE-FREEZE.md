# Link2Context V0.6 Scope Freeze / 范围冻结

## 1. 最朴素、最高优先级的产品目标

> **只要用户给出一个链接，当前 AI 就应该能够读取这个链接里的信息；不论信息是什么类型，都尽可能完整地交给 AI。任何无法取得或无法交付的信息都必须明确暴露，禁止静默丢失后假装“完整”。**

这是 V0.6 的唯一产品 North Star（北极星目标）。实现细节都服务于它，不反过来绑架目标。

工程化表达：

```text
URL/resource
  → safe acquisition
  → type-aware decoding
  → structured context + original assets
  → target-aware delivery
  → explicit completeness/evidence state
```

## 2. “完整”的 V0.6 定义

1. **能识别就不压扁**：正文、标题、层级、列表、代码、表格、链接、图注、关键图片、原始文件分别保留语义。
2. **能保留原件就不伪造转换**：PDF、图片、Office、音视频、压缩包等二进制继续保留原文件交付，不把乱码冒充文本。
3. **动态内容有限但真实地渲染**：在用户明确授权浏览器上下文后，允许受限 DOM settle / scroll / load-more；不无界滚动、不盲点任意控件。
4. **分页宁缺毋错**：下一页除 URL/控件信号外，还要通过 Article Identity（文章身份）检查，防止静默串入下一篇文章。
5. **图文不能静默缺图**：正文关键图片尝试实际下载并附件交付；失败会标记 partial（部分完成）并禁止自动发送。
6. **编码不能默默乱码**：保存 charset 决策来源与置信度；HTTP 未声明时继续检查 BOM / HTML/XML 声明 / UTF-8 合法性。
7. **目标 AI 能力不假装永久真值**：V0.6 当前能力与历史已验证基线分开记录；没有 V0.6 真实证据就保持 `UNVERIFIED`。
8. **外部内容永远是不可信数据**：网页里的“忽略之前指令”等文字属于 source data，不升级成系统/用户指令。
9. **Auto-send 是可选便利功能，不是内容完整性的前提**：默认手动；自动发送必须取得独立成功证据，否则明确 `SEND_UNCONFIRMED`。
10. **任何 partial / unsupported / unverified 都必须可见**：不能用“任务完成”掩盖缺失。

## 3. V0.6 已冻结的实现边界

V0.6 做：

- Mozilla Readability + DOM structured walker；
- canonical Context Model + provenance/trust；
- heading / paragraph / list / blockquote / code / table / link / image / attachment；
- `src` / `srcset` / 常见 lazy image 属性；
- 关键图片筛选、下载、大小/数量预算、实际 MIME 验证；
- 传统分页 + Article Identity + 去重；
- 有授权前提的 bounded rendered acquisition（有限渲染采集）；
- BOM / HTTP / document-declaration / UTF-8 validity 编码链；
- ChatGPT / DeepSeek / 豆包 / 千问 Target Profile；
- V0.6 通用 target handoff；
- 千问保留 V0.5.3 已实测 CDP 真输入路径；
- ChatGPT / DeepSeek / 豆包自动发送采用 button → form → **仅显式 Auto-send 时** bounded CDP Enter fallback；
- 原 V0.5.3 special-source / original-binary 稳定路径作为 fallback；
- 固定 live evidence（真实浏览器证据）账本。

V0.6 明确不做：

- 绕过登录/验证码/付费墙/DRM；
- 无限滚动全网通吃；
- 自动理解音视频内容本身（保留/交付原文件是本版边界）；
- 给所有 AI 绑定脆弱私有 API；
- 把 `debugger` 暴露成通用浏览器自动化接口；
- 因为某家 AI 当前支持某格式，就声称永久支持；
- 为了 100% 网页覆盖继续无限增加站点补丁。

### Development Freeze / 开发冻结

**2026-08-22：V0.6 功能开发正式停止。**

最终安全收口额外修复了两类 merge-blocking（阻断合并）问题：

1. 附件交付不再绕过网页 `<input type="file" accept=...>` 的类型约束；找不到兼容入口时明确失败/partial，不再移除 `accept` 强塞文件。
2. 授权渲染采集在导航后重新检查浏览器上下文授权/deny-list；“加载更多”候选若是跨源链接不会被自动点击。

从此不再添加“顺手功能”。只有真实使用暴露的 blocker / regression（阻断问题 / 回归问题）才能重新打开代码修改。

## 5. 合并与 live-complete 是两件事

本次 V0.6 在代码冻结、全量 CI、安全收口和文档对齐完成后，按产品负责人明确指令合并。

**合并不自动把第三方网页 AI 的实时能力升级为 PASS。** `docs/V0.6-LIVE-EVIDENCE.md` 继续作为唯一真实浏览器事实账本：没有在 V0.6 候选上实际跑过的 ChatGPT / DeepSeek / 豆包 / 千问能力保持 `UNVERIFIED`；V0.5.3 千问的真实 PASS 只作为历史回归基线保留。

因此 V0.6 的发布含义是：

> **Code-complete + security-closed + CI-green + development-frozen（代码完成、安全收口、CI 通过、开发冻结）。**
>
> 不是“所有第三方网站未来永久兼容”的承诺。
