## 为什么从 V0.5.2 转到 V0.5.3

V0.5.2 的自动化测试虽然已经很完整，但真实浏览器测试暴露了一个关键问题：在千问页面中，扩展生成的内容可能“肉眼可见”，却没有进入千问真正的受控编辑器状态。

真实失败现象包括：

- 提取文本出现在输入区；
- 文本无法正常删除；
- 用户后来手动输入几个字后，发送按钮才真正可用；
- 最终发送出去的只有后来手动输入的文字。

这说明 DOM（页面元素树）可见状态不能作为网页 AI 真实交付成功的证明。V0.5.3 因此停止继续在 V0.5.2 旧发送层上打补丁，重新收口当前 runtime（运行时）和千问专用交付路径。

## 最终千问方案

中国千问入口：

- `qianwen.com`
- `www.qianwen.com`
- `qwenwork.cn`

采用：

```text
真实用户粘贴 URL
→ Link2Context 抓取 / 分类 / 清洗
→ Chrome debugger 临时 attach
→ CDP Input.insertText 写入真实编辑状态
→ 状态签名验证 + blur/refocus 复核
→ 手动发送，或显式 Auto-send 时用 CDP 真实 Enter
→ 独立页面证据确认发送
→ debugger detach
```

关键点：

- 不使用 `execCommand('insertText')` 作为中国千问文本交付路径；
- 不用 `innerHTML` / `textContent` 直接画假文本；
- 不伪造 `InputEvent` 冒充框架真实状态；
- 自动发送不依赖猜测千问发送按钮；
- 失败时返回明确错误，不允许“看起来成功”。

## `debugger` 权限边界

V0.5.3 manifest 新增 Chrome `debugger` 权限。因为这是强权限，实现中做了以下硬限制：

- 只接受内部 `L2C_QIANWEN_CDP` 消息；
- 只允许顶层 frame；
- 只允许 `qianwen.com` / `qwenwork.cn` 及其子域；
- 只允许 `insertText` / `pressEnter` 两种动作；
- 文本单次上限 180,000 字符；
- 每次临时 attach，`finally` 中 detach；
- 如果已有 DevTools / 其他 debugger 占用，则明确失败；
- 不增加任意 `Runtime.evaluate`、Network 捕获、Cookie / Local Storage / 凭据读取能力。

详见根目录 `SECURITY.md`。

## 其他 V0.5.3 修复

### 自动发送

- Manual review（手动确认）仍是默认模式；
- Auto-send（自动发送）必须显式开启；
- 通用站点点击发送按钮不代表成功；
- 必须看到生成状态、消息离开 composer（输入区）等独立证据，否则 `SEND_UNCONFIRMED`。

### STOP

STOP 现在覆盖：

- 网络抓取；
- 重试 / 分页；
- 授权浏览器读取；
- 附件等待；
- 编辑器交付；
- 自动发送等待。

### 多页文章

支持的安全分页信号包括：

- `<link rel="next">`；
- 明确“下一页 / Next”链接；
- 数字分页；
- `data-href` / `data-url` / `data-next-url` / `data-page-url`；
- `data-page` / `data-page-number` / `data-pageno`；
- 同源 `onclick location`。

边界继续保留：同源、同文章 URL family、最多 8 页、总响应大小限制、可取消。

不保证任意 SPA 无限滚动或所有“加载更多”页面。

### PDF / 图片 / 二进制

原始二进制继续保持原文件附件，不进入文本归一化路径。
